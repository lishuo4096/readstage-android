# 0.1.1 连续听读与导演修复

## 普通听读预生成检查

参照 PC 工程 `services/tts/player.ts` 的 lookAhead=6 与最多 2 路请求，新增有界预生成队列。启动前准备当前片段及后续 5 段（文末按剩余数量），播放时滚动补充，缓存移除已播片段。状态栏显示已预生成数量。

提前准备下一段原生 MediaPlayer，通过 setNextMediaPlayer 自动接续，避免结束后才发 HTTP、写音频和 prepare。配置、音色、文件、跳段改变时清理旧队列、取消语音请求并释放下一段播放器；暂停保留现有缓冲。

Android 15 / emulator-5582，真实 MiMo 合成：启动显示「已预生成 5 段」，连续两次原生自动切换时下一播放器已处于播放状态；暂停与跳段取消通过。证据：`evidence/continuity-normal.json`。

## AI 导演分段检查

旧实现硬性比较返回条数，模型合并相邻 ID 或漏段时直接报数量不匹配。现在按原始 ID 检查覆盖，接受字符串整数 ID 和 from/to 闭区间，展开合并范围，同时保留对重复、重叠、越界和无效角色／音色的拒绝。

缺失时保留有效结果，仅重新请求缺少的原始 ID；提供具体错误反馈，多次失败后缩小为单段修复。新请求显式提供 expectedIds，强调后续批次不要从零重新编号；文本输出预算提高到 12000 tokens。修复请求继承已有角色表，不改写正文、不用猜测数据填补缺失。

Android 15 真实 MiMo 文本模型：14 段跨两个批次，识别 2 个角色并完整覆盖 14 个原始 ID；导演听读同样预生成 5 段，连续原生切换、暂停、跳段取消通过。证据：`evidence/continuity-director.json`。
